# Playwright E2E tests

End-to-end coverage for Burj-Goal focuses on the core user journeys: empty state, add / complete / reopen / delete goals, and localStorage persistence under the `burj-goal:v1` key.

## Prerequisites

```bash
npm install
npx playwright install chromium
```

## Commands

```bash
# Manual exploration only (port 3000) — not used by e2e
npm run dev

# Run the suite (always build + production server on port 3001)
npm run test:e2e

# Interactive UI mode
npm run test:e2e:ui

# Headed browser
npm run test:e2e:headed

# Open the last HTML report
npx playwright show-report
```

On CI, set `CI=1` for retries / single worker (see [playwright.config.ts](../playwright.config.ts)). The e2e webServer never reuses an existing process.

## Suite map

- [tests/e2e/goals.spec.ts](e2e/goals.spec.ts) covers the main goal lifecycle flows.
- [tests/e2e/multitab.spec.ts](e2e/multitab.spec.ts) covers cross-tab persistence behavior.
- [tests/fixtures/test.ts](fixtures/test.ts) provides shared fixtures for app bootstrapping.
- [tests/pages/goal-page.ts](pages/goal-page.ts) holds the page-object helpers used by the specs.

## Test layout

```text
tests/
  README.md           # this file
  e2e/                # Playwright specs (`testDir`)
  fixtures/           # extended `test` / `expect` + app-open helpers
  pages/              # thin page objects
  screenshots/        # opt-in README screenshot capture
```

- Put new user flows in `e2e/*.spec.ts`.
- Prefer page-object methods for repeated UI actions; reserve one-off assertions for the spec itself.
- Keep shared setup such as storage clearing, seeding, and navigation in the fixtures or page object.

## Selector strategy

Prefer accessibility locators:

- `getByRole`, `getByLabel`, `getByText`
- Existing labels: “New goal”, “Add floor”, `aria-label="Goals"`, toggle/delete `aria-label`s, tower `aria-label="Goal tower"`
- Floor nodes: `[data-floor="N"]`

Avoid CSS-module class names because they are brittle and not part of the public UI contract.

## Isolation strategy

[lib/useTasks.ts](../lib/useTasks.ts) keeps an in-memory cache backed by localStorage. Tests isolate carefully by clearing or pre-seeding storage before the app boots:

- Empty start: [tests/pages/goal-page.ts](pages/goal-page.ts) clears storage via `evaluate`, then reloads so the app re-reads the empty state.
- Seeded start: the same page object can inject tasks via `addInitScript` before the app JavaScript runs.

Do not use a persistent `addInitScript` that clears storage, because it would wipe data on later reloads. The shared fixture and page-object helper handle this for you.

## README screenshot

Regenerate the committed hero image when the UI or layout changes:

```bash
npm run docs:screenshot
```

This runs Playwright with [playwright.screenshot.config.ts](../playwright.screenshot.config.ts) (port 3002, production build), seeds demo goals, and writes [docs/burj-goal.png](../docs/burj-goal.png). The PNG is committed to the repo and is not generated by git hooks.

## webServer

Port roles:

| Port | Purpose |
|------|---------|
| 3000 | `npm run dev` — human exploration only |
| 3001 | E2E suite ([playwright.config.ts](../playwright.config.ts)) |
| 3002 | README screenshot capture ([playwright.screenshot.config.ts](../playwright.screenshot.config.ts)) |

E2e always runs `npm run build && npx next start --port 3001` with `reuseExistingServer: false`, so a running `next dev` on :3000 cannot affect results.
